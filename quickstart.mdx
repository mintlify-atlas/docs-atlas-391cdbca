This guide walks you through spinning up a full local development environment for TestForge — both the Next.js frontend and the FastAPI backend — running side by side on your machine.

<Note>
  This guide covers **local development** only. For a production deployment using Docker Compose, see the [Deployment](/deployment) guide.
</Note>

## Prerequisites

Make sure the following tools are installed and available on your `PATH` before proceeding.

| Tool | Minimum Version | Notes |
|---|---|---|
| **Node.js** | 20+ | Used by the Next.js frontend |
| **pnpm** | Latest | Recommended package manager (`npm i -g pnpm`) |
| **Python** | 3.11+ | Required by the FastAPI backend |
| **PostgreSQL** | 16+ | Can be run via Docker (covered below) |
| **Docker** | Latest | Used to run the local database |
| **Git** | Latest | For cloning the repository |

## Setup Steps

<Steps>
  <Step title="Clone the Repository">
    Clone the TestForge repository to your local machine and navigate into the project root.

    ```bash
    git clone <repository-url>
    cd testforge-v1.2
    ```
  </Step>

  <Step title="Start the Database">
    TestForge uses PostgreSQL 16. The easiest way to run it locally is via Docker Compose, which starts a pre-configured Postgres container.

    ```bash
    docker-compose up -d
    ```

    This starts the `postgres` container (mapped to host port `4935`) and automatically runs database migrations via the `migrate` service before anything else starts.

    <Note>
      The `migrate` container runs once and exits successfully after applying the schema. The `backend` and `frontend` services depend on it completing before they start.
    </Note>

    Verify the database is healthy:

    ```bash
    docker ps
    ```

    You should see `testforge-postgres` with a status of `healthy`.
  </Step>

  <Step title="Set Up the Backend">
    Navigate to the `backend/` directory, create a Python virtual environment, install dependencies, and copy the environment template.

    ```bash
    cd backend

    python -m venv venv

    # macOS / Linux
    source venv/bin/activate

    # Windows
    # venv\Scripts\activate

    pip install -r requirements.txt

    cp .env.example .env
    ```

    Now open `backend/.env` and fill in the required values:

    ```env
    # Database
    DATABASE_URL=postgresql://postgres:password@localhost:4935/testforge

    # App
    DEBUG=True
    TESTING=False
    TEST_EXAM_CENTER_ID=

    # Upload
    UPLOAD_DIR=uploads
    MAX_UPLOAD_SIZE=10485760

    # Security
    SECRET_KEY=your-secret-key-here
    CORS_ORIGINS=http://localhost:3000

    # URLs
    NEXT_PUBLIC_APP_URL=http://localhost:3000

    # Logging
    LOG_LEVEL=INFO
    ```

    <Warning>
      Set `TESTING=True` and supply a `TEST_EXAM_CENTER_ID` only when running the backend test suite. Leave both unset for normal development.
    </Warning>
  </Step>

  <Step title="Set Up the Frontend">
    Navigate to the `frontend/` directory, install Node dependencies with pnpm, and copy the environment template.

    ```bash
    cd ../frontend

    pnpm install

    cp .env.example .env.local
    ```

    Open `frontend/.env.local` and configure all required variables:

    ```env
    # Database (Drizzle connects directly to Postgres)
    DATABASE_URL=postgresql://postgres:password@localhost:4935/testforge

    # Better Auth
    BETTER_AUTH_SECRET=your-better-auth-secret
    BETTER_AUTH_URL=http://localhost:3000

    # Google OAuth
    GOOGLE_CLIENT_ID=
    GOOGLE_CLIENT_SECRET=

    # Razorpay
    NEXT_PUBLIC_RAZORPAY_KEY_ID=
    RAZORPAY_KEY_ID=
    RAZORPAY_KEY_SECRET=
    RAZORPAY_WEBHOOK_SECRET=

    # Resend Email
    RESEND_API_KEY=
    NEXT_PUBLIC_EMAIL_FROM=
    NEXT_PUBLIC_REPLY_TO=
    EMAIL_FROM=
    REPLY_TO=

    # App URLs
    NEXT_PUBLIC_APP_URL=http://localhost:3000
    NEXT_PUBLIC_HOSTED_URL=http://localhost:3000
    NEXT_PUBLIC_BACKEND_URL=http://localhost:8000

    # Environment
    NODE_ENV=development
    LOG_LEVEL=info

    # Docker (leave empty for local dev)
    IS_DOCKER=
    ```

    <Tip>
      For local development you can leave Razorpay, Google OAuth, and Resend variables empty if you do not need payments, social login, or email functionality during your session.
    </Tip>
  </Step>

  <Step title="Push the Database Schema">
    From the `frontend/` directory, push the Drizzle schema to your running Postgres instance. This creates all application tables.

    ```bash
    pnpm db:push
    ```

    <Note>
      This command uses `drizzle-kit push` under the hood and reads your `DATABASE_URL` from `frontend/.env.local`. Run this every time you make schema changes during development.
    </Note>
  </Step>

  <Step title="Start the Backend">
    From the `backend/` directory (with your virtual environment still active), start the FastAPI development server with hot reload enabled.

    ```bash
    cd ../backend

    uvicorn main:app --reload
    ```

    The backend API is now available at:

    ```
    http://localhost:8000
    ```

    Interactive API docs are served at `http://localhost:8000/docs` (Swagger UI) and `http://localhost:8000/redoc`.
  </Step>

  <Step title="Start the Frontend">
    Open a new terminal, navigate to the `frontend/` directory, and start the Next.js development server.

    ```bash
    cd frontend

    pnpm dev
    ```

    The application is now available at:

    ```
    http://localhost:3000
    ```
  </Step>
</Steps>

## Verify the Setup

Once both servers are running, open `http://localhost:3000` in your browser. You should see the TestForge login page. The frontend communicates with the backend at `http://localhost:8000` via the `NEXT_PUBLIC_BACKEND_URL` variable you configured.

## Useful Development Commands

Run these from the `frontend/` directory:

```bash
# Push schema changes to the database
pnpm db:push

# Generate Drizzle migration files
pnpm db:generate

# Open Drizzle Studio (visual database browser)
pnpm db:studio

# Run frontend tests
pnpm test

# Lint the codebase
pnpm lint
```

Run these from the `backend/` directory (virtual environment active):

```bash
# Run backend tests
pytest

# Start the server with a custom port
uvicorn main:app --reload --port 8000
```
