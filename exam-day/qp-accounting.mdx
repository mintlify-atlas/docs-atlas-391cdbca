QP Accounting is the process of verifying that every question paper packet dispatched by the MSBTE distribution center has actually arrived at the exam center. TestForge tracks this at the subject–session–date level through the `qp_inventory` table, giving exam officers a real-time reconciliation view before papers are issued to blocks.

## Two-Stage Inventory Flow

<CardGroup cols={2}>
  <Card title="QP Inventory Setup" icon="upload">
    Done in **Exam Setup → QP Inventory** before exam day. Uploads expected packet counts (derived from the timetable) so the system knows what to expect from the distribution center for every subject.
  </Card>
  <Card title="QP Accounting (Exam Day)" icon="calculator">
    Done in **Exam Day → QP Accounting** on the morning of each exam day. Records actual packets received and QP-per-packet count, then flags any shortfall or surplus.
  </Card>
</CardGroup>

## The `qp_inventory` Table

Each row represents one subject–session–date combination for an exam center:

| Column | Type | Description |
|---|---|---|
| `exam_center_id` | `uuid` | Foreign key to the exam center |
| `day` | `integer` | Exam day number (Day 1, Day 2, …) |
| `date` | `timestamp` | Exam date for this row |
| `session` | `text` | `"Morning"` or `"Afternoon"` |
| `subject_code` | `text` | MSBTE subject code |
| `expected_students` | `integer` | Students registered from timetable |
| `expected_packets` | `integer` | `ceil(expectedStudents / 50)` |
| `received_packets` | `integer` | Actual packets received on exam day (default 0) |
| `received_qps` | `integer` | Total QPs calculated from received packets (default 0) |

<Note>
  Expected packets are auto-generated by `generateQPInventoryFromTimetable()` if no inventory record exists when the officer first opens the QP Accounting page for a given date. The formula is `ceil(totalStudents / 50)` per timetable entry.
</Note>

## Pre-Exam Inventory Setup

Before exam day begins, the inventory module under **Exam Setup** provides a full read-only view of all expected packets across the entire examination cycle.

<Steps>
  <Step title="Upload Inventory Data">
    Navigate to **Exam Setup → QP Inventory**. Use the file uploader (`UniversalFileUploader` with `fileType="inventory"`) to upload a CSV/Excel file containing subject codes, expected students, expected packets, session, and exam day.
  </Step>
  <Step title="Review the Inventory Table">
    After upload, the sortable data table shows every subject across all sessions and days. Click any row to open the **Inventory Detail Modal**, which shows packet counts, discrepancy details, and estimated QP shortage or surplus.
  </Step>
  <Step title="Filter and Export">
    Use the Session filter (Morning / Afternoon) or the search bar to narrow down the list. Click **Export** to download a CSV of the current filtered view.
  </Step>
</Steps>

## Exam Day QP Accounting Workflow

<Steps>
  <Step title="Open QP Accounting">
    Navigate to **Exam Day → QP Accounting**. The page defaults to today's date and fetches inventory records automatically via `getQPInventory(today)`.
  </Step>
  <Step title="Select Date and Session">
    Use the **Examination Date** date input and the **Session** dropdown (Morning / Afternoon / All Sessions) to scope the view. Click **Fetch Inventory** to load the records.

    ```typescript
    // Server action called on fetch
    await getQPInventory(date: Date, session?: string);
    ```

    If no inventory exists for the selected date, the system auto-generates records from the timetable via `generateQPInventoryFromTimetable()`.
  </Step>
  <Step title="Enter Received Packets">
    For each row in the inventory table, type the actual number of packets received from the distribution center into the **Received Packets** column. The field is highlighted in amber if the value differs from the expected count.
  </Step>
  <Step title="Enter QP Per Packet">
    Enter the QP-per-packet count in the adjacent column (default is 50 per packet). The system auto-calculates `receivedQps = receivedPackets × qpPerPacket` on every keystroke.
  </Step>
  <Step title="Review Discrepancies">
    A discrepancy badge in the page header counts how many subjects have `expectedPackets ≠ receivedPackets`. Rows with mismatches are highlighted with an amber background.

    The stats strip above the table shows:
    - **Subjects** — total subject–session entries for the day
    - **Expected Students** — sum across all entries
    - **Received Packets** — running total as you fill in values
    - **Packet Discrepancy** — absolute difference (highlighted amber when non-zero)
    - **Completion Rate** — percentage of subjects with matching counts
  </Step>
  <Step title="Submit Inventory">
    Click **Submit Inventory**. A confirmation dialog lists all discrepant subjects:

    ```text
    Subject Code    Expected    Received
    22519           12          10          ← shortage
    22306           8           9           ← surplus
    ```

    Choose **Submit with Discrepancies** to record the actual values (discrepancies are logged for audit), or **Cancel** to correct the entries first.

    ```typescript
    // Bulk save action
    await bulkUpdateQPInventory({
      date: Date,
      records: Array<{ id: string; receivedPackets: number; qpPerPacket: number }>,
    });
    ```
  </Step>
  <Step title="Export or Print">
    After submission, use **Export** to download a CSV file named `qp-inventory-YYYY-MM-DD.csv`, or **Print** to send the accounting sheet directly to the printer for physical records.
  </Step>
</Steps>

<Warning>
  **Packet reconciliation is mandatory before issuing papers to blocks.** MSBTE requires that any packet shortage or surplus be documented in the official QP Accounting report. Submitting with discrepancies logs them permanently against the exam center record — they cannot be deleted, only corrected by re-submitting with updated values. Always verify counts directly from the sealed packets before clicking Submit.
</Warning>

## Status Indicators

Each row in the accounting table shows one of three statuses:

| Status | Condition | Colour |
|---|---|---|
| **Complete** | `receivedPackets >= expectedPackets` | Emerald green |
| **Warning Mismatch** | `receivedPackets ≠ expectedPackets` | Amber |
| **Pending** | `receivedPackets = 0` | Neutral grey |

## Missing Packets on the Dashboard

The Exam Day Dashboard reads `qpInventoryStatus.completion` from `getExamOfficerDashboard()`. If completion is below 80 %, the **Inventory** metric card turns amber, alerting the officer without requiring them to open the QP Accounting page.

```typescript
qpInventoryStatus: {
  totalExpected: number;   // sum of expectedPackets across all entries
  totalReceived: number;   // sum of receivedPackets across all entries
  pending: number;         // totalExpected - totalReceived (floored at 0)
  completion: number;      // round(totalReceived / totalExpected × 100)
}
```

<Tip>
  Run **Generate** (toolbar button) on the QP Accounting page the evening before each exam day to pre-populate expected packet counts from the timetable. This saves time on the morning of the exam and lets you spot any missing timetable entries in advance.
</Tip>
