TestForge generates every official MSBTE examination report — from examinee instructions to question paper packet accounting — directly from live data stored in your database. No spreadsheets, no manual entry. Navigate to **Reports → MSBTE Reports**, select the format you need, choose a date where required, and print a perfectly formatted A4 document in seconds.

## Available Formats

All formats are rendered using the `msbte-report-layout` wrapper, which enforces MSBTE's standard A4 portrait layout with the official MSBTE logo, examination season/year, exam centre name and code, date, session metadata, and signature fields in the footer.

| Format | Name | Description |
|--------|------|-------------|
| **F1** | Instructions to Examinees | Two-page document listing General Instructions, Instructions regarding writing answer books, and Special Instructions for examinees. Displayed at the examination hall entrance. |
| **F2** | QP Bundle Receipt (Controller to DC) | Receipt issued by the Officer-in-Charge on receiving question paper bundles from the Controller of Examination. Shows the exam centre code, day, date, session, bundle details, and total bundle count, using the actually received packet counts. |

## How Data Is Populated

Every MSBTE report fetches its data live from the database at the time of generation:

- **Seating and block data** comes from the block allocation module after supervisor assignment is complete.
- **Attendance and absent numbers** are pulled from timetable entries updated on the exam day dashboard.
- **QP inventory** (packets received, expected, returned) is sourced from the question paper accounting module.
- **Staff details** (supervisor names, reliever names, UIDs) come from the staff management module.
- **Exam centre metadata** (name, code, season, year, distribution centre code) is resolved from the authenticated user's exam centre record.

<Note>
Reports that require a specific date — such as F2, F3, F3A, and F9 — display a date selector screen before rendering the report. Only dates that have inventory or timetable data are shown in the selector.
</Note>

## Printing a Report

All MSBTE reports share the same print workflow powered by the `react-to-print` library.

<Steps>
  <Step title="Open the report page">
    Navigate to **Reports → MSBTE Reports** and select the format you want to print (e.g., Format 2).
  </Step>
  <Step title="Select a date (if prompted)">
    For date-dependent reports, choose the examination date from the available dates dropdown. Only dates with existing inventory or timetable data appear in the list.
  </Step>
  <Step title="Review the on-screen preview">
    The report renders as an A4 preview on screen, populated with live data. Verify the exam centre name, code, date, and content before printing.
  </Step>
  <Step title="Set the number of copies">
    Use the **Copies per block** number input in the control bar to choose how many copies to print (1–5). Copy 1 is labelled "Forwarded with answer book bundle"; Copy 2 is "For office record".
  </Step>
  <Step title="Click Print All">
    Click the **Print All** button. The browser's native print dialog opens with the page size pre-set to **A4 portrait**. Select your printer and confirm.
  </Step>
</Steps>

<Tip>
The `msbte-report-layout` wrapper enforces exact A4 dimensions (`210 mm × 297 mm`) with zero browser margins via the `@page { size: A4; margin: 0; }` CSS rule. For best results, ensure **Headers and Footers** is **disabled** in the browser print dialog, and **Background graphics** is **enabled** so table borders and shading print correctly.
</Tip>

## Layout Architecture

The `msbte-report-layout.tsx` component exports two report primitives:

- **`ReportLayout`** (default export) — wraps a single-page report with a standardised header (MSBTE logo, exam season/year, centre name/code, date, session) and an optional footer with supervisor and officer signature fields.
- **`MultiPageReport`** (named export) — renders an array of `ReportPageData` objects as individual A4 pages, with per-page headers derived from each page's data. Used for multi-page formats such as F1 (two instruction pages) and block allocation sheets with paginated seat grids.

Both components accept a `compact` prop that reduces padding and font size from `11pt` to `10pt` to fit more content on a single page without altering the A4 boundary. Both portrait (`210 mm × 297 mm`) and landscape (`297 mm × 210 mm`) orientations are supported via the `printLandscape` prop.
