TestForge Reports are the platform's own internal report formats, separate from the official MSBTE F-series. These reports are designed for operational use by the exam centre team: planning block layouts before the exam, briefing supervisors, tracking attendance during the day, and producing duty rosters for the entire examination period. All reports are rendered using the `testforge-report-layout` wrapper, which applies a clean Inter-font A4 layout branded with your exam centre name.

## Block Allocation Report

The Block Allocation report (`block-allocation.tsx`) generates two types of output in a single print run:

1. **Block Allotment Summary** — A tabular overview of all blocks for the selected date and session, sorted by block number. Each row shows block number, location and supervisor name, scheme, subject code and name, seat range, student count, and timeslot. A grand total row summarises blocks, subjects, and students.

2. **Block Detail Pages** — One page per block showing a header grid (date, session, block number, location, supervisor, total students), a per-subject breakdown table (scheme, subject code and name, seat range, students, timeslot), and a visual seat grid. The seat grid is rendered using one of four configurable seating templates that control the direction in which seat numbers flow through the columns.

**Seating templates:**

| Template | Fill Direction |
|----------|---------------|
| 1 (default) | Right-to-left columns, alternating top-to-bottom / bottom-to-top per column |
| 2 | Right-to-left columns, always top-to-bottom |
| 3 | Left-to-right columns, always top-to-bottom |
| 4 | Left-to-right columns, alternating top-to-bottom / bottom-to-top per column |

The template and column distribution for each block are configured in the Block Management module and stored in the `blocks` table.

<Steps>
  <Step title="Navigate to the report">
    Go to **Reports → Block Allocation**. The page loads available timetable dates automatically.
  </Step>
  <Step title="Select date and session">
    Choose the examination date and session (Morning, Afternoon, or All) from the session selector. Click **Generate**.
  </Step>
  <Step title="Review the allotment summary">
    The summary table renders first. Verify block counts, student totals, and supervisor assignments.
  </Step>
  <Step title="Set copies and print">
    Use the **Copies** control to set how many copies of each block detail page you need, then click **Print**.
  </Step>
</Steps>

## Daily Summary Report

The Daily Summary report (`daily-summary.tsx`) provides an at-a-glance attendance overview for a single date and session. It combines allocation data with live absent numbers and copy-case counts fetched from the timetable entries.

Each row in the report represents one subject-block combination and shows:
- Serial number, block number and location
- Subject code, name, and scheme
- Supervisor name
- Total, present, absent, and copy-case student counts
- A remarks column

The footer row shows the grand totals and an overall attendance rate percentage. If the data spans more than 8 rows, the report automatically paginates across multiple A4 pages.

<Note>
Absent numbers and copy-case counts are only populated after they have been recorded on the **Exam Day Dashboard**. Running this report before the session ends will show zeroes for absent and copy-case columns.
</Note>

## Staff Duty Report

The Staff Duty report (`staff-duty.tsx`) produces a complete duty roster covering the entire examination period — not just a single date or session. It loads all allocations and all staff records simultaneously, then groups duty entries by staff member, sorted alphabetically by name.

Each staff row shows:
- Serial number, staff name, UID, and department
- One sub-row per unique date-session combination the staff member is assigned to, with the date, session badge (Morning / Afternoon), and student count

The report auto-loads on page open without requiring a date selection, since it spans all dates. It supports 1–5 copies and shows a grand total of staff and students in the footer.

---

## Supervision Report

The Supervision report (`supervision.tsx`) is a per-session duty schedule grouped by supervisor. Unlike the Staff Duty report (which spans all dates), the Supervision report is for a single selected date and session.

Rows are grouped by supervisor — each supervisor appears once with their name and UID shown using `rowspan`, and one sub-row per subject assigned to that block. Each sub-row shows block number, location, scheme, subject, student count, and timeslot. The footer shows totals for supervisors, blocks, and students.

<Tip>
Generate the Supervision report the morning before each examination session and post it outside the examination hall. Supervisors can check their assigned block and location without needing to contact the control room.
</Tip>

## Report Layout Architecture

All TestForge reports use `testforge-report-layout.tsx`, which exports:

- **`ReportLayout`** (default export) — wraps a single-page report with a header showing the exam centre name prominently, metadata fields (code, season, year, date, session), report title, and an optional footer with signature fields and a "Generated using TestForge®" credit.
- **`MultiPageReport`** (named export) — renders paginated reports from a `ReportPageData[]` array. Each page merges the shared header config with per-page metadata. Supports a configurable copies control (1–5) via `onCopiesChange` and an optional copy-info footer label.

The TestForge layout uses **Inter** as the body font (versus Times New Roman in the MSBTE layout) to distinguish internal reports from official MSBTE formats.

```typescript
// Minimum header config for any TestForge report
header={{
  title: 'DAILY EXAM SUMMARY',
  description: 'Day-wise examination statistics and attendance overview',
  examCenter: {
    name: examCenter?.name,
    code: examCenter?.code,
    season: examCenter?.season,
    year: examCenter?.examYear,
    session: 'Morning',
    date: new Date(selectedDate),
  },
}}
```

Both portrait (`210 mm × 297 mm`) and landscape (`297 mm × 210 mm`) orientations are supported via the `printLandscape` prop.
